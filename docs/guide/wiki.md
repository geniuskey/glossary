# 위키 지식 창고

위키는 용어 자체의 사전적 정의가 아니라, 그 용어가 실제 업무에서 어떻게 쓰이는지를
쌓는 공간이다. 원칙·프로세스·플레이북·결정 배경처럼 여러 용어를 함께 설명하는 문서를
만들고, 하나 이상의 용어를 연결할 수 있다.

## 화면과 주소

| 경로 | 역할 |
|---|---|
| `/w` | 위키 문서 목록 |
| `/w/new` | 새 문서 작성 |
| `/w/[slug]` | 위키 문서 읽기 |
| `/w/[slug]/edit` | 문서 편집 |
| `/g/[slug]` | 용어 상세 |

`/w/<slug>`는 이제 위키 주소다. 과거에 용어 상세를 가리키던 `/w/<용어>` 링크는 위키
문서가 없을 때 `/g/<용어>`로 호환 리다이렉트된다. 위키 슬러그는 용어 슬러그와 겹치지
않도록 저장 시 검사하며, `new`와 `page`는 화면 주소와 충돌하므로 예약되어 있다.

## 문서 상태

- `draft`: 편집 중인 문서. 로그인한 사용자는 볼 수 있지만 AI 근거와 RAG 검색에서는 제외한다.
- `published`: 검토를 마친 공식 업무 맥락. 현재 리비전이 RAG 색인 대상이다.
- `archived`: 더 이상 사용하지 않는 문서. 읽기 목록과 RAG에서 제외한다.

편집자와 API 키는 `draft`만 만들거나 수정할 수 있다. `published`·`archived` 전환은
관리자만 할 수 있으며, 승인자와 승인 시각이 함께 기록된다. 편집자는 초안으로 저장한
뒤 관리자에게 공개 검토를 요청한다.

문서가 수정될 때마다 본문·메타데이터·연결 용어의 스냅샷과 revision 번호가 저장된다.
연결 용어는 첫 번째가 대표 용어이고, 나머지는 관련 용어로 표시된다.
Confluence 등 원문을 관리하는 외부 URL도 문서에 남길 수 있다. 회의록 전체를 복사하지 않고
검토된 지식만 위키에 작성하며, 문서의 `원문 출처 URL`에서 최신 회의 맥락을 확인한다.

## AI와 RAG

공개 위키는 용어집·회의 자료와 별도 vector 인덱스를 사용한다. 챗봇 근거에서는 위키를 `W`,
용어집을 `G`, 회의 자료를 `M`으로 구분해 인용한다. 초안이 실수로 공식 답변에 섞이지
않도록 published 문서만 색인하며, 문서가 초안·보관으로 바뀌면 기존 청크도 제거한다.

직접 API를 사용할 때는 다음 엔드포인트를 사용한다.

- `GET/POST /api/v1/wiki`
- `GET/PATCH /api/v1/wiki/{slug}`
- `POST /api/v1/rag/wiki/search`

자세한 요청 형식과 오류 규약은 [RAG 검색 API](/api/rag)와 [API 개요](/api/)를 참고한다.
