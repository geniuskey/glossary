# 함께 정리

`/contribute`는 내용이 덜 채워진 용어를 찾아 보완하고, AI가 만든 제안을 필요한 것만
반영하는 작업 공간이다. `/contribute/fields`에서는 특정 필드가 비어 있는 용어만 따로 모아
집중해서 처리할 수 있다. 모든 로그인 사용자가 사용할 수 있으며, AI를 연결하지 않아도 직접
편집할 수 있다.

## 작업 영역

| 영역 | 용도 | 주요 작업 |
|---|---|---|
| **정리 대기** | 보완할 용어를 찾는 기본 목록 | 검색·업무 분야·부족한 정보로 필터링하고, 표의 행에서 편집하거나 AI 검토를 요청한다. |
| **제안 검토** | AI와 규칙이 만든 변경안을 확인 | 왼쪽 **검토 대상** 목록에서 용어를 고르고 현재 값과 제안을 비교한 뒤 제안별로 승인하거나 거절한다. |
| **중복 후보 검토** | 같은 개념으로 보이는 용어 쌍을 판단 | 규칙 후보를 비교하고, 병합·분리·보류 중 하나를 결정한다. |
| **필드 보완** | 표기와 특정 정보가 비어 있는 용어를 집중 보완 | 하위 작업인 **표기 정비**, **한줄 정의**, **도메인**, **업무 분류**에서 해당 필드만 모아 처리한다. |
| **내 작업** | 나중에 다시 볼 AI 제안 모음 | 제안 카드에서 **내 작업에 저장**한 항목을 다시 열거나 삭제한다. |
| **AI 작업 링크** | AI 작업 현황과 다음 작업 확인 | 헤더의 **AI 작업** 링크에서 검토 필요·진행 중·실패 건수를 보고 제안을 검토하거나 실패한 작업을 다시 요청한다. |

## 가장 빠른 작업 순서

1. **정리 대기**에서 `부족한 정보`나 `업무 분야`를 선택해 범위를 좁힌다.
2. 한 건만 처리하려면 행의 **내용 채우기** 또는 **AI 검토 요청**을 사용한다. 여러 건은
   체크박스로 선택한 뒤 **일괄 AI 검토 요청**을 누른다. 일괄 요청은 현재 페이지에서 최대
   60건까지 가능하다.
3. 오래 걸리는 요청은 **AI 작업**에서 상태를 확인한다. **검토 필요** 상태가 되면
   **제안 검토**로 이동하고, 실패하면 원문을 확인한 뒤 **다시 요청**한다.
4. **제안 검토**에서 왼쪽 목록으로 다음 용어를 선택한다. 현재 용어의 순서는 유지되며,
   용어를 선택했다고 목록이 그 항목을 1번으로 다시 정렬하지 않는다.
5. 제안 카드의 현재 값과 제안 값을 비교한다. 필요한 제안만 **승인하고 저장**하고,
   맞지 않는 제안은 **거절** 또는 규칙 제안의 **이번에 건너뛰기**를 누른다.
6. 본문을 한줄 정의로 보완할 때는 사이드바의 **필드 보완**에서 **한줄 정의** 작업을 열고,
   행별 제안을 확인하고,
   필요하면 입력란을 고친 뒤 **승인**한다.
7. 분류를 채울 때는 사이드바의 **필드 보완**에서 **도메인** 또는 **업무 분류** 작업을 열고,
   특정 단어로 필터링하고,
   **AI 추천**을 확인한다. 추천이 적절하면 **승인하고 저장**, 아니면 추천을 버리고 직접
   수정하거나 다시 추천받는다. 각 작업은 해당 분류가 비어 있는 용어만 보여준다.
8. 대표명·확장명·별칭·약어가 엉켜 있거나 도메인 문맥으로 보완할 수 있을 때는
   **표기 정비**를 연다. 규칙 확인·문맥 보완·AI 검토 대기 대상을 필터링할 수 있으며,
   현재 값과 문제 사유를 먼저 확인한 뒤 개별 **AI 검토** 또는 현재 페이지의 **AI 검토 시작**을
   실행한다. AI가 제안한 값은 필드별로 직접 고쳐 **승인**하거나 **거절**할 수 있다.
9. AI 제안이 틀렸다고 판단되면 **오탐으로 숨김**을 선택한다. 판단이 아직 어렵다면 **보류**로
   남겨 계속 보이게 하고, 나중에 처리할 제안은 **내 작업에 저장**한다. 오탐·보류는 같은
   생성기 버전의 공용 제안에 적용되고, 내 작업은 본인에게만 적용된다.

## 작업별 사용법

### 정리 대기

목록은 카드가 아니라 표로 표시된다. 용어, 필요한 정보, 최근 수정 시각과 작업을
한 행에서 확인할 수 있다. `용어 검색`, `업무 분야`, `부족한 정보` 필터는 URL에 보존되므로
페이지를 새로 열어도 같은 범위를 다시 볼 수 있다. 60건을 넘으면 페이지 이동을 사용한다.

AI 연결이 켜져 있을 때만 체크박스와 **일괄 AI 검토 요청**을 사용할 수 있다. 이미 대기 중이거나
처리 중인 용어는 다시 선택할 수 없다. 일괄 요청은 선택한 용어의 현재 리비전을 함께 보내며,
그 사이 용어가 바뀐 항목은 요청에서 제외될 수 있다.

### 제안 검토

왼쪽 **검토 대상** 사이드바에서 용어를 검색·선택하고 오른쪽 상세 영역에서 검토한다.
각 용어에는 `N개`, `완료`, `준비 중`, `대기` 상태가 표시된다. 목록은 정리 우선순위를
유지하며, 선택한 용어를 최상단으로 옮기지 않는다.

상세 영역에는 현재 한줄 정의·업무 분야·본문 근거와 검토할 제안이 나온다. 제안은
`규칙` 또는 `AI 판단` 출처와 함께 표시되며, 필드별로 처리한다. 한 제안을 승인하면
용어가 즉시 새 리비전으로 저장된다. 관계 제안은 승인한 관계만 챗봇의 관련 용어 탐색에
사용된다.

각 AI 제안에는 **오탐으로 숨김**, **보류**, **내 작업에 저장** 상태를 별도로 기록할 수
있다. 숨김은 같은 생성기 버전의 같은 리비전 제안을 공용 목록에서 제외하고, 보류는
`보류됨` 표시와 함께 목록에 남긴다. 내 작업에 저장한 제안은 다른 사람의 목록에는 영향을
주지 않으며 `/contribute?tab=mine`에서 다시 열 수 있다. 다시 검토하기를 누르면 개인
저장이 해제되고 원래 작업 화면에서 제안을 확인한다.

### 중복 후보 검토

표기가 겹치거나 URL 끝에 숫자 접미사가 붙은 **후보 쌍**이 먼저 나온다. 목록에서 두 용어의
표기·정의·도메인을 나란히 확인하고 **두 용어 비교**를 눌러 AI 판정과 근거를 확인한다.
검색창에 URL 슬러그를 직접 넣어 후보가 목록에 없어도 검토할 수 있다. AI 결과는 **같은 개념**,
**다른 개념**, **판단 보류**로 나뉜다.

**같은 개념**이면 양쪽 중 하나를 대표 용어로 선택해 병합한다. 병합 전에 대표 용어와 보관될
원본을 다시 확인하며, 대표 용어의 이름·정의를 유지하고 양쪽 표기·분류·본문과 원본 이력을
보존한다. 기존 URL은 대표 용어로 연결된다. **다른 개념으로 유지**와 **판단 보류**도 저장되므로
같은 후보 쌍을 다시 반복해서 검토하지 않는다. 어느 한쪽의 리비전이 바뀌면 이전 판단은 만료되어
다시 검토 대상으로 돌아온다.

### AI 작업

상단에서 `검토 필요`, `실패`, `처리 중`, `대기`, `전체 작업` 건수를 확인한다. 상태 필터는
URL에 보존되며, 기본 목록은 사람이 바로 처리할 수 있는 항목을 먼저 보여준다. 각 항목에서
요청 방식·대상 리비전·요청 시각과 처리 시작·완료 시각을 확인할 수 있다.

`검토 필요` 항목은 **제안 검토**로 이동한다. 실패한 항목은 **원문 확인**으로 내용을 먼저
보고 **다시 요청**할 수 있다. AI 작업 화면을 열면 오래 멈춘 처리와 대기 작업을 자동으로
재개하며, 필요하면 **처리 재개**를 눌러 다시 확인할 수 있다. AI가 자동 검토하도록 설정된
경우와 사용자가 직접 요청한 경우는 같은 작업 목록에서 관리된다.

### 필드 보완: 한줄 정의

본문이 있고 한줄 정의가 비어 있는 용어가 한 표에 계속 표시된다. 각 행에는 용어, 본문
근거, LLM 한줄 정의 제안과 처리 버튼이 있다. AI가 켜져 있으면 표에 들어갈 때 제안을
준비하며, 제안이 없거나 실패한 행은 **LLM 정리** 또는 **다시 정리**로 실행할 수 있다.

제안은 textarea에서 한 줄로 직접 다듬을 수 있다. **승인**을 누르는 순간 해당 용어의
한줄 정의를 저장하고 이 행을 목록에서 제거한다. 다른 사람이 먼저 수정해 리비전이 바뀌면
승인되지 않으므로 최신 본문을 다시 확인한다.

### 필드 보완: 도메인·업무 분류

두 작업은 각각 해당 분류가 비어 있는 용어만 보여주는 집중 작업 화면이다. 상단 필터로 용어명·
표기·URL에 특정 단어가 들어간 항목만 좁힐 수 있다. 업무 분류 작업에서는 현재 도메인을 별도
컬럼으로 함께 확인할 수 있다. 용어의 한줄 정의나 본문을 참고하고
페이지를 열면 AI 추천이 자동으로 준비되며, 같은 용어 리비전의 기존 추천은 다시 사용한다. 추천 분류와 근거가 표시되면 수정한 뒤 **승인하고 저장**하거나,
추천을 버리고 직접 선택할 수 있다. **저장**하면 일반 용어 수정 API와 현재 리비전을 함께
사용하며, 다른 사람이 먼저 수정한 경우에는 충돌을 알려 주고 행을 남긴다.

### 필드 보완: 표기 정비

**표기 정비**는 값이 비어 있는 용어뿐 아니라 다음과 같이 기존 표기의 정합성이 의심되는
용어를 찾는다.

- 대표 영문·국문 표기가 없거나, 영문 필드에 한글이 들어간 경우
- 도메인 문맥으로 보완할 수 있는 대표명·확장명·별칭이 비어 있는 경우
- 대표명·확장명·별칭·약어가 서로 중복되거나 추가 표기의 종류·언어가 맞지 않는 경우
- 같은 추가 표기가 다른 용어에도 등록되어 동일 개념 여부를 확인해야 하는 경우

목록은 한 번에 40건씩 표시하며, 페이지를 이동하거나 용어 필터로 범위를 좁힐 수 있다.
목록의 **현재 값**과 규칙상 확인 사유를 검토한 뒤 개별 **AI 검토** 또는 **AI 검토 시작**을
누른다. 페이지 진입만으로 AI를 호출하지 않으며, 사용자가 시작한 현재 페이지의 일괄 검토만
최대 2건씩 병렬로 실행한다. AI는 현재 용어의
이름·도메인·업무 분류·본문과 용어집 안의 관련 용어를 근거로 제안하며, 의미가 여러 개이거나
근거가 부족한 값은 `확인 필요`로 남긴다.
대표명·확장명은 문자열을 직접 다듬을 수 있고, 추가 표기는 표준 표기·약어·확장명·별칭·
비권장·금지 중 종류 변경 또는 추가·삭제 후보로 검토한다. 모든 승인·저장은 일반 용어 수정과
같이 새 리비전을 만들고, 다른 사람이 먼저 수정했다면 충돌로 중단된다.

## AI를 사용할 때

관리자가 **관리자 패널 → AI 연결**에서 공급자·모델·API Key를 설정하고 연결 시험을
통과시켜야 한다. 저장된 비밀값을 사용하려면 서버의 `GLOSSARY_ENCRYPTION_KEY`가
32자 이상으로 고정되어 있어야 한다. AI는 선택 기능이며 연결되지 않은 상태에서도
정리 대기와 직접 편집은 계속 사용할 수 있다.

AI 검토·필드 보완의 한줄 정의·분류 추천은 현재 용어의 이름·분류·본문을 외부 공급자에 보낼 수 있다.
조직의 데이터 처리 정책에 맞는 공급자를 선택하고, 생성된 결과는 저장 전에 사람이
확인한다. `draft`는 보완이 필요하다는 뜻이고 비공개나 미승인 상태를 뜻하지 않는다.

## 주소

| 주소 | 화면 |
|---|---|
| `/contribute` | 정리 대기 |
| `/contribute?tab=agent` | 제안 검토 |
| `/contribute?tab=duplicates` | 중복 후보 검토 |
| `/contribute?tab=mine` | 내 작업: 개인 저장 AI 제안 |
| `/contribute?tab=queue` | AI 작업 링크 |
| `/contribute/fields` | 필드 보완 개요 |
| `/contribute/fields?field=identity` | 필드 보완: 표기 정비 |
| `/contribute/fields?field=definition` | 필드 보완: 한줄 정의 |
| `/contribute/fields?field=domain` | 필드 보완: 도메인 |
| `/contribute/fields?field=category` | 필드 보완: 업무 분류 |
| `/contribute?tab=definitions` | 이전 주소 → 필드 보완: 한줄 정의 |
| `/contribute?tab=domains` | 이전 주소 → 필드 보완: 도메인 |
| `/contribute?tab=categories` | 이전 주소 → 필드 보완: 업무 분류 |

AI 생성·승인 API의 요청 형식은 [AI 연결과 챗봇 API](/api/ai), 백업과 암호화 키 보관은
[운영 안내서](/operations)를 참고한다.
