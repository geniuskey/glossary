# 함께 정리

`/contribute`는 내용이 덜 채워진 용어를 찾아 보완하고, AI가 만든 제안을 필요한 것만
반영하는 작업 공간이다. 모든 로그인 사용자가 사용할 수 있으며, AI를 연결하지 않아도
직접 편집할 수 있다.

## 다섯 탭

| 탭 | 용도 | 주요 작업 |
|---|---|---|
| **정리 대기** | 보완할 용어를 찾는 기본 목록 | 검색·업무 분야·부족한 정보로 필터링하고, 표의 행에서 편집하거나 AI 검토를 요청한다. |
| **제안 검토** | AI와 규칙이 만든 변경안을 확인 | 왼쪽 **검토 대상** 목록에서 용어를 고르고 현재 값과 제안을 비교한 뒤 제안별로 승인하거나 거절한다. |
| **중복 정리** | 같은 개념으로 보이는 용어를 합치기 | 후보를 AI로 비교하고, 같은 개념일 때 대표 용어를 선택해 병합한다. |
| **AI 검토 큐** | AI 작업 진행 상태 확인 | 대기·검토 중·완료·실패 건수와 각 용어의 재검토·제안 보기 작업을 확인한다. |
| **한줄 정의 정리** | 본문은 있지만 한줄 정의가 없는 용어 보완 | 용어별 본문 근거와 LLM 제안을 표에서 한 번에 보고, 필요한 행만 수정·승인한다. |

## 가장 빠른 작업 순서

1. **정리 대기**에서 `부족한 정보`나 `업무 분야`를 선택해 범위를 좁힌다.
2. 한 건만 처리하려면 행의 **내용 채우기** 또는 **AI 검토 요청**을 사용한다. 여러 건은
   체크박스로 선택한 뒤 **일괄 AI 검토 요청**을 누른다. 일괄 요청은 현재 페이지에서 최대
   60건까지 가능하다.
3. 오래 걸리는 요청은 **AI 검토 큐**에서 상태를 확인한다. **완료** 상태가 되면
   **제안 보기**로 이동한다.
4. **제안 검토**에서 왼쪽 목록으로 다음 용어를 선택한다. 현재 용어의 순서는 유지되며,
   용어를 선택했다고 목록이 그 항목을 1번으로 다시 정렬하지 않는다.
5. 제안 카드의 현재 값과 제안 값을 비교한다. 필요한 제안만 **승인하고 저장**하고,
   맞지 않는 제안은 **거절** 또는 규칙 제안의 **이번에 건너뛰기**를 누른다.
6. 본문을 한줄 정의로 보완할 때는 **한줄 정의 정리**에서 행별 제안을 확인하고,
   필요하면 입력란을 고친 뒤 **승인**한다.

## 탭별 사용법

### 정리 대기

목록은 카드가 아니라 표로 표시된다. 용어, 부족한 정보, 상태, 최근 수정 시각과 작업을
한 행에서 확인할 수 있다. `용어 검색`, `업무 분야`, `부족한 정보` 필터는 URL에 보존되므로
페이지를 새로 열어도 같은 범위를 다시 볼 수 있다. 60건을 넘으면 페이지 이동을 사용한다.

AI 연결이 켜져 있을 때만 체크박스와 **일괄 AI 검토 요청**을 사용할 수 있다. 이미 대기 중이거나
처리 중인 용어는 다시 선택할 수 없다. 일괄 요청은 선택한 용어의 현재 리비전을 함께 보내며,
그 사이 용어가 바뀐 항목은 요청에서 제외될 수 있다.

### 제안 검토

왼쪽 **검토 대상** 사이드바에서 용어를 검색·선택하고 오른쪽 상세 영역에서 검토한다.
각 용어에는 `N개`, `완료`, `준비 중`, `대기` 상태가 표시된다. 목록은 정리 우선순위를
유지하며, 선택한 용어를 최상단으로 옮기지 않는다.

상세 영역에는 현재 한줄 정의·업무 분야·본문 근거와 검토할 제안이 나온다. 제안은
`규칙` 또는 `AI 판단` 출처와 함께 표시되며, 필드별로 처리한다. 한 제안을 승인하면
용어가 즉시 새 리비전으로 저장된다. 관계 제안은 승인한 관계만 챗봇의 관련 용어 탐색에
사용된다.

### 중복 정리

표기가 겹치거나 URL 끝에 숫자 접미사가 붙은 용어가 먼저 후보로 나온다. 검색창에 URL
슬러그를 직접 넣어 다른 용어를 검토할 수도 있다. AI 결과는 **같은 개념**, **다른 개념**,
**판단 보류**로 나뉜다.

**같은 개념**인 경우에만 **이 용어를 대표로 병합 승인**을 사용할 수 있다. 대표 용어의
이름·정의를 유지하고 양쪽 표기·분류·본문과 원본 이력을 보존하며, 기존 URL은 대표 용어로
연결한다. AI가 판단 보류나 다른 개념으로 분류한 항목은 병합하지 않는다.

### AI 검토 큐

상단에서 `현재 처리 중`, `대기`, `검토 중`, `완료`, `실패` 건수를 확인하고 아래 목록에서
요청 방식·대상 리비전·요청 시각을 본다. 실패한 항목은 **내용 확인 및 재검토**로 원문을
확인한 뒤 다시 요청하고, 완료한 항목은 **제안 보기**로 이동한다. AI가 자동 검토하도록
설정된 경우와 사용자가 직접 요청한 경우가 같은 큐에서 관리된다.

### 한줄 정의 정리

본문이 있고 한줄 정의가 비어 있는 용어가 한 표에 계속 표시된다. 각 행에는 용어, 본문
근거, LLM 한줄 정의 제안과 처리 버튼이 있다. AI가 켜져 있으면 표에 들어갈 때 제안을
준비하며, 제안이 없거나 실패한 행은 **LLM 정리** 또는 **다시 정리**로 실행할 수 있다.

제안은 textarea에서 한 줄로 직접 다듬을 수 있다. **승인**을 누르는 순간 해당 용어의
한줄 정의를 저장하고 이 행을 목록에서 제거한다. 다른 사람이 먼저 수정해 리비전이 바뀌면
승인되지 않으므로 최신 본문을 다시 확인한다.

## AI를 사용할 때

관리자가 **관리자 패널 → AI 연결**에서 공급자·모델·API Key를 설정하고 연결 시험을
통과시켜야 한다. 저장된 비밀값을 사용하려면 서버의 `GLOSSARY_ENCRYPTION_KEY`가
32자 이상으로 고정되어 있어야 한다. AI는 선택 기능이며 연결되지 않은 상태에서도
정리 대기와 직접 편집은 계속 사용할 수 있다.

AI 검토와 한줄 정의 정리는 현재 용어의 이름·분류·본문을 외부 공급자에 보낼 수 있다.
조직의 데이터 처리 정책에 맞는 공급자를 선택하고, 생성된 결과는 저장 전에 사람이
확인한다. `draft`는 보완이 필요하다는 뜻이고 비공개나 미승인 상태를 뜻하지 않는다.

## 주소

| 주소 | 화면 |
|---|---|
| `/contribute` | 정리 대기 |
| `/contribute?tab=agent` | 제안 검토 |
| `/contribute?tab=duplicates` | 중복 정리 |
| `/contribute?tab=queue` | AI 검토 큐 |
| `/contribute?tab=definitions` | 한줄 정의 정리 |

AI 생성·승인 API의 요청 형식은 [AI 연결과 챗봇 API](/api/ai), 백업과 암호화 키 보관은
[운영 안내서](/operations)를 참고한다.
